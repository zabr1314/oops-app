# Android 会后事项、任务来源与恢复链路

日期：2026-10-14。基于主分支的P0来源绑定、任务板和录音豆副本保护，纳入尚未提交的会后事项与转写收尾前置，以及本轮手机数据对齐。

## 行为

- 已存纪要派生待办、决定、待定事项，原话和人工核对分别保留；无纪要时继续逐句队列，不另调模型。事项确认、业务完成和飞书创建分别记录，负责人由人选。
- `/v1/tasks` 保留正式飞书 `items`，独立返回核对站 `parsed_items/parsed_status` 与App已人工确认的 `meeting_items`。项目汇总确认待办与决定；同来源已创建任务保留关联回执，避免重复候选。
- 首页与记忆展示会议待办入口。外部核对返回刷新；候选读取中、失败或来源失效时不继续使用旧正文。会话删除按会话与请求编号撤回相关缓存，拒绝迟到响应。空核对队列不代表业务完成，缺时区的旧日期不推算。
- 新录音冻结规范化后端URL及mock归属，不保存凭据。旧无归属文件保留待核，不自动迁移到当前服务。异常退出恢复先同步未到期原始定稿并核对回包，再确认结束；停止等待ASR真实收尾，不用空结束掩盖缺句。
- 服务变化清旧异步建议和未提交草稿，活动记录/收尾时不允许跨端点切换。已提交操作继续按原端点查询。召回保存绑定本次原会话与原句快照。
- 保留主分支的服务端来源合同、上下文依赖、单调来源版本、独立保留短依据及未知外部结果保护。来源失效撤回未执行许可；已尝试且结果未知时只查询原操作/可信GUID，不以新op重复创建。
- 日常采用服务签名的 `scope=daily` 合同和五分钟内存receipt双重核对；所选原句及上下文总量不超过280字/20句，不按邻句默认保存大量日常原文。合同不证明现实发言已独立核验，也不能替代归档会议的来源合同。

## 核对站接入依赖

三场16个待办的来源是已部署的私有核对站事项API；本PR不包含核对站新的生成、身份迁移或自动导入功能。服务端私有 `label-app-tasks.json` 明确配置启用范围、事项ID与指纹，未配置时返回disabled，不将示例答案冒充生产数据。源站变更或指纹失效时撤下该场旧正文。

适配只读取固定loopback源站，限制并发、响应体和整份快照期限，不生成模型、不写人工答案、不自动创建飞书任务。配置、完整会议、音频、人工答案、APK和发布备份均不进入仓库。

## 数据清理与交付边界

真实手机的三段早期合成测试保存片段已可恢复归档；一场无录音/核对/关联成果的调试会话已备份后通过既有删除接口清理。此前旧飞书测试任务已删除，原操作日志保留防重。这些是已执行的数据清理，PR不在启动或页面读取时自动重放删除。

10月13/14日手机交付版本已做APK打包、覆盖安装和实际只读回读：核对站16条候选、正式任务0，App已确认纪要待办当前为0；不能复制源站人次答案填充App会议确认。服务端保护文件及手机业务文件保持。私有回执仅保存在本地忽略目录。

本PR另与随后更新的主分支P0代码合并。先前APK/部署回读属于合并前交付版本，不代表本PR最终组合版本已重新安装或实录验收。本次提交只进行必要静态核对与受保护运行时检查，未运行测试或重新构建；携带的相关测试是此前已有改动。

原发布包固定旧源码哈希的历史升级脚本未纳入本PR，不能将其套在本PR源码上执行。后续真实发布须同时准备事项/质量模块、`action_sources.py`、`task_board.py`和Android合同变更，保留服务私有签名密钥、配置与原数据。

录音豆真实事件、账户/项目权限隔离、本人飞书授权、工作助手App执行及真人内容质量验收仍按各自接入依赖处理，不以本轮数据汇总代替。
