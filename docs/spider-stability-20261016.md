# 蜘蛛页播放与断线恢复（2026-10-16）

用户明确要求测试经常断开、播放中途卡住和服务器数据未刷新。本轮仅修原蜘蛛只读页面，不启动录音、模型、ASR或外部发送。

## 已复现的问题

- 线上长会议在75%位置、60倍速播放后停在73:34 / 95:37，按钮仍显示暂停，后续观察进度不再变化。控制台记录 `funnel-spider.js:95` 的负圆半径 `IndexSizeError`。原因是落点使用较晚的 `performance.now()`，同一帧绘制使用较早的RAF时间，未限制负动画年龄，导致绘制异常且下一帧未登记。
- 线上已出现“历史服务读取超时…已清除”的空白页。读取失败清空当前会话ID，手动播放同时关闭自动切换，后续轮询失去目标，网络恢复也无法自行续播。
- 会后引擎收到同源新增原话/结果时无条件重建，进度、速度与播放状态被清零。

## 修复

- 限制蜘蛛落点动效年龄至0–1，避免负半径；动画循环提前登记后续帧，显示异常保留进度与恢复入口。
- 列表临时失败时单独核对当前正文，正文仍有效就继续播放。正文网络/超时/临时服务失败仍立即清除可见私有内容，仅在内存保留会话ID、数字进度、倍速和播放意图，每5秒尝试新授权读取，成功后续播；不保存旧正文或旧ETag，不写本机持久化。
- 明确撤权、删除和到期停止自动恢复；换源、示例、本机文件、退出取消恢复，迟到回包不能覆盖新选择；隐藏页面停止读取且撤回待恢复的播放意图。
- 同源会后更新保留所处阶段、阶段进度、速度、播放与滚动；仅分类轨迹变化不重建会后；换源与清除仍重置。
- 稳定岔口增量绘制到缓存，动态原话和新判断单独更新；DOM20fps、画布30fps，暂停与隐藏停止持续绘制。分栏隐藏导致布局为0时保留最后有效画布，避免切回后的零尺寸缓存异常。

## 原文自动滚动补齐

用户反馈 `history.readonly` 仍不实时滚动。原实现仅在进入thinking状态时滚动，20fps DOM与60倍速常直接跳到done；初始滚动时间0还会误触4秒冷却。改为每次播放DOM更新后跟随最新可见原话，包含逐字出现、直接done和结束帧；seek到未选句时也定位。坐标使用行/滚动容器rect差加scrollTop，长句露出句末，目标按真实滚动范围限制；即时滚动避免不断重启smooth动画。手动滚动保留4秒冷却，播放持续跟踪使冷却后无需等新的状态转换就能恢复；同源更新在冷却期恢复旧位置，播放态不再后置覆盖跟随结果。

新增3项滚动回归与原live updates用例共4项通过，静态核对和28文件运行时完整性通过。原站只更新 `funnel.js`，备份 `/var/backups/oops-history/scroll-20261016T055605Z`，无服务重启，45份服务器保护文件不变、模型调用0。线上初次打开已将最新末句完整放进原文视口；60倍速从22:54播放到54:51时原文scrollTop由4221移至26323，当前句末仍在视口内；55:22继续可见。原文手动回看与恢复跟随的回归通过，页面已恢复自动接入模式。实屏及数字记录放在 `build/spider-scroll-20261016/`。没有用测试会议冒充新实录。
