# 长会议分段兜底：源码已部署，默认关闭（2026-10-16）

本次优先完成转写后文字理解统一 Sol。分段兜底源码已随同轮窄补丁部署生产，开关保持未设置；没有启用分段、运行分段模型请求或重跑历史会议。实际部署/手机交付见 `docs/sol-text-rollout-20261016.md`。

## 开关与输入预算

- `OOPS_MINUTES_PART_CHARS` 未设置、空值或为 `0` 时，继续当前完整全文输入和三份独立生成的原行为，不增加请求、不截取中段。
- 明确设为正整数才启用预检。预算按 Python Unicode 字符数计算，包含纪要系统提示、会议头、原话 ID/说话人/人工核对信息、另一 ASR 参考和分段提示；不是供应商精确 token 计量，不能据此保证任何模型容量。部署方须根据实际模型输入容量另行选择预算，并留足输出余量。
- `OOPS_MINUTES_MAX_PARTS` 默认 `8`，允许显式设为 1–64。所有完整原话预先规划；单句连同提示超预算、预算无效或所需段数超上限，在纪要请求前明确失败，不只处理前几段。
- 只有超过预算的会议才进入分段；预算内会议仍使用当前全文路径。开启后超过预算的会议需要 `3 × 段数` 次纪要调用；本实现不发起额外全场归纳调用，也没有运行这些调用。

## 完整处理与失败语义

分段以完整原话为边界，保留原编号和次序；尾段即使只有 1–4 句仍会处理。三份独立生成各自处理全部段，全部完成后才按原多数规则投票；分段数量不是票数，版本号继续为 `5`。

任何分段失败，本场均不发布部分纪要、不持久化中间分段结果，也不以其他两份成功冒充本场完整成功。未开始的后续分段会停止；已经发出的请求不能假装撤销或未计费。长会错误沿用停止本场自动重试的模型错误类型，返回安全原因，不自动重发 POST。

## 跨段解释的边界

分段不能证明后段没有反对、补条件、回答前问或撤回前段决定。因此分段中的待办、决定、日程及待查问题均进入 `undecided`，带原类别、分段编号和来源 ID；不直接拼成 `actions`、`decisions` 或 `follow_ups`。事项仍可按既有人工核对流程改类别、编辑内容并选择负责人。

`overview` 只说明已处理的段数、原话数和仍需全场核对，不采用第一段概览代表整场。`topics` 与 `segment_summaries` 明确标注分段范围并保留来源；读取纪要时返回对应当前原话。元数据 `long_meeting.cross_part_resolved=false` 明确跨段结论尚未解决。分段内容仍受既有来源修订、删除、期限和人工核对边界约束。

覆盖范围只表示本次现有转写中的全部输入句已处理，不证明原音归档、ASR收尾或识别内容完整正确。分段概览和讨论要点沿用当前纪要的代表完整生成份数展示方式，不冒充逐项投票共识；待核对事项继续经过三份多数投票。

本轮没有提升纪要版本、重算旧缓存、修改供应商配置或启用开关。源码阶段仅做必要静态核对；随后已按明确授权部署，但尚未执行分段模型调用或真实长会分段验收，不能据源码上线声称跨段问题已解决。
