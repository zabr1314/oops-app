## 下一场真实会议的验收记录

开始前固定本次 APK 哈希、后端版本、音源、会议编号、开始时间及明确保存选择。使用同一实际音源；不要把模拟录音豆或旧音频回放当真人实测。

会上记录：

1. 收音/ASR是否连续、断网重连是否恢复、是否有缺句；同步或保存失败是否明确提示且能重试。
2. 实时清单是否出现有来源的真实任务，是否合并重复说法、排除举例和空话；后续发言到来后是否继续更新；P0只是候选，不能自动认领或创建外部任务。
3. 点清单能否回到正确原话，核对说话人和负责人是否分别处理；记录误报、漏报、错误归属及出现时间。
4. 结束后检查会议保存回执、纪要主题及主线/其他任务，逐条核对原文；手动名和议程仍优先于纪要主题。
5. 修改或舍弃来源后，旧纪要/清单授权是否撤回，历史文档是否仅保留历史入口。单独确认的短依据与摘要不恢复全文。

验收表至少记录 `session_id / 时间点 / 入口 / 原话ID / 预期 / 实际 / 证据 / 严重度 / 处理 / 复验`。技术连通与人工内容质量分别判定；仍有未核对项时不能写“真实会议验收通过”。当前该环节为待执行。
