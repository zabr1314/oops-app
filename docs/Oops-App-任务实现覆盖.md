# Oops App 任务区实现覆盖

实现文件：`oops-app/src/features/Tasks.tsx`。组件返回手机内内容，由共享App外壳提供顶部、底栏和滚动容器。所有文字输入均使用共享键盘组件；没有修改受保护的移动运行环境。

## 已实现的页面与行为

| 原规格 | App入口 | 实际行为 |
|---|---|---|
| T01 / T03 / T04 | `tasks`，mode为待我处理/我的待办/助手工作 | 根据同一任务对象和业务/助手状态过滤，支持搜索、优先级和结束状态筛选；修改后列表同步变化。 |
| T02 | `task-detail` | 展示当前责任、期限、目标、助手状态与成果入口；来源定位相关会话转写。 |
| T05 / T29 | `task-accept`；T29另有TASK-033详情 | 核对目标、本人责任及期限后才接受。支持明确有效日期时间或无固定期限；空白和模糊期限阻断。接受不启动AI，TASK-033独立保存。 |
| T06 | `task-reject` | 必填婉拒原因，更新业务状态并保留活动。 |
| T07 / T08 | `task-transfer` / `task-transfer-response` | 选择明确接收人并填写原因；等待回应时不改变原负责人。提供演示同意、婉拒和撤回，接收人同意后才改变责任与重新核对授权。 |
| T09 / T17 | `task-result` | 成果列表、库存资料、来源、版本及消息/邮件/日程入口；库存与KPI任务各自保存成果。 |
| T10 | `task-edit` / `task-ask` / `task-attachment` | 可编辑标题、目标、期限、优先级和逐项验收；记录具体缺资料问题；选择已有资料或填写补充说明。无id的task-edit创建新草稿。 |
| T11 | `task-plan` | 查看该任务的准备步骤、依赖、个人保存位置与预计额度；进入承接、授权、额度或缺资料处理。 |
| T12 | `task-authorize` | 必须已承接，并勾选指定资料读取与个人草稿允许；存储范围。没有允许则不能准备。 |
| T13 | `task-progress` | 开始后约2.4秒生成本地文档/PPT内容，更新对应任务；暂停、停止会使旧准备回调失效。停止助手不会取消业务。 |
| T14 | `task-failure` | 显示未完成项；補资料后只重试原任务，不复制任务、不重做该版本已成功的成果。可以保留成果并停止。 |
| T15 | `task-budget` | 检查上限、已用和预计额度；可切换完整框架/PPT与仅提纲。额度不足时阻断准备，与项目预算独立。 |
| T16 | `task-change` | 保存具体变更，增加需求版本，停止旧准备，重新核对范围；旧成果与回执保留并标记待复核。 |
| T18—T21 | `task-preview` / `task-artifact-edit` / `task-versions` | 文档正文和PPT逐页预览；可改标题、正文或单页内容，另存新版本；打开旧版比较并导出文本提纲。 |
| T22 / T23 | `task-send` / `task-send-confirm` | 实际编辑发送账号、收件对象、全文与附件版本；每次修改撤销核对勾选。先核对，再由底部确认面板展示全文并模拟提交。支持保存草稿和复制正文。 |
| T24 | `task-email` | 实际编辑发件账号、对象、抄送、主题、正文、附件；必填检查、草稿保存和二次确认。缺资料问题可带入询问邮件正文。 |
| T25 | `task-calendar` | 实际编辑参与人、标题、完整年月日/时间、议程、目标日历；无效日期或先后时间阻断，已有模拟安排冲突需处理；二次核对后模拟创建。 |
| T26 | `task-receipt` | 展示本地模拟对象、当次内容和操作时间；同一任务、方式、对象及正文重复提交返回原回执，不覆写已发生记录。 |
| T27 | `task-history` | 按时间展示承接、回应、授权、暂停、资料、修改、版本、验收及模拟操作记录。 |
| T28 | `task-complete` | 必须已承接、有成果且逐项勾选验收；取消需原因并停止未完成准备，保留成果与回执。 |

其他route：`task-create`是新草稿入口；`task-artifact-edit`是成果编辑入口。未知入口显示可返回的空状态，不显示规格文稿。

## 状态与数据

- 业务任务和AI状态分别保存在同一Task对象。接受工作只修改业务；允许范围、开始准备、停止和完成验收有各自操作。
- 准备回调核对原任务的token和当前AI状态，暂停、停止、取消或改需求后不会被旧回调覆盖。
- 任务内保存草稿、验收标准、补充资料、问题、允许范围、额度与成果版本；App共享数据统一承载任务、活动与回执。
- 成果、任务列表、详情、历史和来源引用同一对象；KPI、库存、资料卡建议不混用责任或产物。

## 验证与实际边界

任务文件已通过严格TypeScript检查；移动运行环境完整性检查通过。App整体验证由父任务执行。

已覆盖T01—T29的功能落位，当前仍未接入录音/识别、真实模型、外部资料读取、真实异步队列、飞书、邮箱或日历服务。转交回应、资料查询和准备均使用本地演示；补充资料是名称/说明及既有资料引用，并非真实文件上传。PPT支持逐页内容编辑与预览，导出为文本提纲，尚无真实PPTX生成或下载。所有发送和日历结果都明确为模拟回执，不会操作真实账号。
