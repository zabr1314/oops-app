# Oops App 任务区实现覆盖

本轮更新直接实现于 App 页面。主要文件为 `src/features/Tasks.tsx`、`TaskCommunication.tsx`，业务逻辑位于 `src/taskWorkflow.ts`、`taskLogic.ts`、`taskAttention.ts` 和 `communicationLogic.ts`。详情标签和主操作位于共享外壳，滚动内容保持移动运行时的原滚动、键盘、安全区与底部面板。

## 页面与行为

| 入口 | 实际行为 |
|---|---|
| `tasks`：待我处理 | 按决定、补齐跟进、成果核对、来源核对分组；包含本人负责及本人跟进需要处理的工作，默认和首页提醒同一规则。助手失败进入队列；已结束工作退出。 |
| `tasks`：我的待办 | 按逾期、今天、之后、无固定期限和结束分组；本人负责、本人提出、本人跟进、全部关系可筛选，另有搜索、状态和优先级。 |
| `tasks`：助手工作 | 显示准备中、草稿就绪、等待允许、失败与已暂停/停止。助手状态与业务进度分开显示。 |
| `task-detail` | 固定概览、资料、成果、记录。概览显示责任、期限、目标、来源、实际结果和待确认问题；底部随业务阶段显示一个主操作，其他操作放进更多面板。 |
| `task-create` / 无 ID 的 `task-edit` | 仅填名称即可创建本人普通待办，直接进入待做；目标、日期、优先级和完成标准可补充。交付任务需要验收标准。 |
| `task-accept` | 会话建议和他人请求需核对目标、本人责任及有效期限或无固定期限。承接不自动启动助手。 |
| `task-reject` | 必填原因，婉拒退出关注队列，保留原记录与成果。 |
| `task-progress-note` | 记录真实进展与下一次跟进；保存后进入进行中，仍可稍后回来继续。 |
| `task-complete`：人工完成 | 普通行动填写实际结果，确认真实工作已完成，核对可选完成标准即可完成；不要求生成文档或使用助手。 |
| `task-complete`：草稿核对 | 选择明确成果版本，打开正文并核对来源。仅标记所选稿件已核对，业务工作保持原阶段。 |
| `task-complete`：交付验收 | 选择实际交付版本、核对各项标准、填写交付说明并确认已实际交付。完成记录保存对应成果 ID，原历史保留。 |
| `task-edit` / `task-change` | 修改目标、类型、期限及验收要求；来源失效时重选准确会话片段并明确核对。要求变化撤回旧准备授权，旧成果保留，不自动更新其原来源。 |
| `task-plan` / `task-authorize` / `task-budget` | 三个旧入口统一进入助手准备。五种产出方式，实际资料对象勾选、任务原话开关、补充说明和额度；两个明确允许项确认后才开始个人草稿。保存配置可以稍后准备。 |
| `task-progress` | 按本次固定快照准备约 2.4 秒的本地示例草稿。暂停、停止或调整范围使旧回调失效；草稿完成不会自动改变业务为完成。 |
| `task-failure` | 显示失败原因，进入资料或问题补齐；可以按新确认范围重试，历史成果保留。 |
| `task-attachment` | 选择当前可见资料对象，或填写本人补充正文；给已有资料的补充说明独立保存。可移除失效资料，修改后撤回准备授权。没有真实文件上传解析。 |
| `task-ask` | 问题分别显示待回答、已回答、已解决；保存具体对象、实际答复与跟进时间。没有答复不能标为已回答或已解决。确认已解决的答复可明确附入任务资料。 |
| `task-transfer` / `task-transfer-response` | 保存请求 ID、原负责人、原业务状态、接收对象、原因和跟进时间。等待回应不改负责人；演示同意后才更换责任。婉拒/撤回恢复原阶段，重复回应不能再处理同一请求。 |
| `task-result` | 显示各类型最新实际成果、来源、核对状态与版本；可保存本人交付物，不必使用助手。选择明确版本提交验收；核对后的资料可以附回关联会话。 |
| `task-preview` / `task-artifact-edit` | 按实际 ID 阅读所选版本，PPT 逐页查看或编辑；另存新版本并保留原稿。旧来源失效时先核对任务，再对当前正文和有效来源重新确认；复核勾选在来源版本或正文变化后失效。 |
| `task-versions` | 选择两个实际版本，比较正文新增、删除和保留内容；显示标题变化，打开指定旧版或新版。 |
| `task-send` / `task-send-confirm` / `task-email` | 编辑明确账号、对象、主题、正文与抄送；勾选实际成果作为附件。应用新选择会同步重起正文和附件，旧稿保留历史。也可明确沿用仍存在的旧附件版本。问题询问绑定具体问题。 |
| `task-calendar` | 编辑参与对象、全文、目标日历与完整年月日时间；检查有效同日时段和本人当前空间的模拟安排冲突。 |
| 沟通确认面板 | 固定当次对象、全文、真实附件 ID/版本/正文快照。提交时再次核对来源、签名、当前空间、附件和日程冲突；编辑后需重新确认。 |
| `task-receipt` | 保存不可被后稿覆盖的本地模拟回执与当次快照。同样内容重复提交返回原回执；按本人和当前空间查看。 |
| `task-history` / 详情记录 | 显示承接、人工进展、问题、转交、配置、来源变化、版本、验收及模拟通信记录。 |
| 更多操作：取消工作 | 必填原因，停止未完成准备，保留成果与历史，退出待处理。输入取消原因时固定操作栏隐藏，面板与输入草稿保留。 |

## 关键逻辑

- 业务阶段、助手草稿和通信操作分别管理。承接工作不等于允许助手；草稿核对不等于实际完成；模拟发送也不自动完成工作。
- 准备请求固定本次模式、预计费用、资料正文与说明、来源、版本及任务要求。资料、说明、范围、来源、授权或预算变化后旧请求停止，不计费、不覆盖新内容。
- 新一轮准备保存独立成果版本；原稿、旧验收和回执不被覆写。原始库存示例不会替代用户当前选定新版正文。
- 来源变更使旧任务及受影响成果待复核、授权撤回。旧 `results` 会先保存为具体成果对象，再标记其原来源失效；只重新选择任务来源不能让旧成果直接通过验收或发送。
- 问题状态需要实际答复。跟进身份在转交同意后保留，到时间或收到答复时进入本人关注。
- 原任务、正式保存数据和页面编辑草稿保留。旧问题迁移为结构化问题；重新打开页面时停止丢失本地计时器的准备，已有成果保留。

## 验证与边界

56 项实际模块逻辑用例覆盖来源传播、权限、生成快照与额度、资料勾选及补充说明、人工完成、交付版本、转交恢复、问题、正文与附件绑定、不可变回执、日程冲突与旧数据迁移。类型检查、生产构建、28 项受保护移动运行时完整性和部署资源检查通过。本轮没有新增浏览器实屏走查或截图，94 页画板与记录体验截图仍为历史参考。

录音、识别、真实模型、外部资料查询、真实异步队列、飞书、邮箱和日历尚未接入。准备、回应和发送仍为明确标注的本地示例。PPT 支持逐页内容编辑与预览、文本提纲下载，尚未生成 PPTX。源码、流程与本地数据可体验；模拟回执不代表真实发送或真实日程写入。
