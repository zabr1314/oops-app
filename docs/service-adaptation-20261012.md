# 现有后端适配与异常状态闭环 · 2026-10-12

本轮基于已合并的 Android 与后端代码，完善 Android H5 的读取、核对和失败恢复。沿用现有会议、项目、任务、人工核对及 AI 纪要接口，没有重新设计后端数据结构，也没有把 29 项能力全部接通。

## 实际适配范围

Android H5 继续通过原生桥调用真实服务。会话、项目和任务使用既有接口；新增 `history.minutes` 桥入口，调用已有的 `GET /v1/meetings/{id}/minutes`，只读取已经保存的纪要。`OopsApi`、`HttpOopsApi`、`MockOopsApi` 与 `MainActivity` 保持这一路径一致。

`action.confirm` 已有的冻结请求、持久化 `op_id`、状态查询与重复操作防护继续保留。已经提交的外部操作仍关联原服务和原操作编号，本轮没有改写这套执行规则。

## 核对必须等保存成功

- 决定、待办负责人等待对应 `review.saved` 才计入已核对并进入下一条。
- 说话人等待 `speaker.corrected(status:"saved")`；`status:"local"` 只表示本机显示已修改，不能当作服务器保存成功。
- 保存期间禁用本条选择及前后切换，防止连续点击产生不同请求。
- 保存失败保留当前核对项、选择和错误提示，可重试相同内容，也可以重新选择或稍后处理。选择保留在当前页面流程中，没有新增跨应用重启的核对草稿存储。
- 回执按操作、会议和原话匹配，其他请求的失败不会使当前核对误跳步。
- 已保存的回执同步当前会议的核对队列与结论显示；被驳回的候选不再继续作为结论展示。
- 撤销人工说话人后，如果模型身份仍未知且原话达到既有核对长度要求，会恢复说话人待核对项；模型已知身份时不增加该项。

## 读取失败与列表缓存

会话、项目和任务首次读取失败时，页面显示持续错误和“重新读取”，不会只短暂提示后永久转圈。刷新失败时保留上次读取的数据，并提示其可能不是最新。

任务缓存按“我的／全部”、状态与本人身份隔离。迟到的另一筛选回包不能覆盖当前列表；本人变更后清除旧身份缓存。首页独立读取本人的未完成任务，不再借用任务页上次打开的团队或已完成任务列表。

打开会议失败时保留请求目标，可重新打开；关闭等待面板后，迟到的打开回包不会强行跳转。项目详情同样匹配请求的项目名称。

## AI 纪要是只读结果

会后概览展示当前服务已存的纪要正文、决定、行动建议、讨论要点、待确认问题和后续跟进建议。可查看对应原话引用；可用的飞书文档由用户点击后打开。

界面分别处理：

| 状态 | 界面行为 |
| --- | --- |
| 读取中 | 显示读取状态，不以旧正文冒充当前结果。 |
| `pending` | 明确会议进行中或纪要仍在整理；用户可重新查询状态。 |
| `ready` | 展示返回的正文及有效原话引用。 |
| `unavailable` | 解释机器人未启用、历史会议未补写、结束状态不明确、服务失败或不支持等原因。 |
| `source_changed` | 撤下旧正文；提示使用最新原文与人工核对结果。旧文档仅保留“历史文档”入口。 |
| 请求失败 | 持续显示读取失败，可手动重试查询。 |

核对保存后立即撤下旧纪要并查询当前状态。每次查询使用独立 `requestId`，旧请求迟到的正文和失败不能覆盖新结果。本轮没有新增自动轮询、重新生成纪要、发送消息或创建日程的动作；重新查询也不会被当成重新生成。

## 切换服务器与权限

原生侧使用 `serviceEpoch` 标识当前服务配置版本，仅在服务地址、Mock 模式或访问凭据真实变化时递增。保存其他无关设置不会使正在等待的读取永久失去回包。

会议、任务、项目、纪要及核对请求在返回或失败前检查版本，旧服务结果不再进入当前界面。行动草稿提取、建议刷新和服务器原声回听同样阻止旧服务迟到结果继续显示或播放。

`backend.changed` 只向 H5 回传后端类型、地址与递增版本号，不包含访问凭据或凭据摘要。H5 在地址、模式或权限版本变化时清除远端缓存、当前纪要及旧核对意图，关闭旧会议、项目和相关面板。旧历史原话面板也会关闭。录音缓冲与原有保存规则不因此被重新定义。

## 公开体验与画板边界

`native-flow.html` 是独立的“安卓流程预览”。构建时从 `android/app/src/main/assets/web` 精确复制当前 H5 源文件到公开预览目录，并记录、校验文件摘要，避免另写一套脱离 Android 的模拟界面。

浏览器模拟桥使用隔离的示例会议和任务，支持正常读取、列表首次失败、核对首次保存失败、纪要处理中、来源变化和纪要首次读取失败等情境。示例修改只保存在当前示例内存，刷新重置；公开站不含真实后端凭据，不会访问真实会议、调用麦克风或写入飞书。

React App 的 **155 张真实页面截图、178 个交互入口** 保持原数量。本轮安卓状态实屏单独展示在安卓流程预览中，不将其混计为 React 页面，也不把浏览器模拟视为 APK 或真机验证。
