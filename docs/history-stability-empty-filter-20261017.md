# 往期会议读取与空记录过滤

2026-10-17。本记录涵盖往期会议读取修复、首版空记录标准及随后已完成的生产/真机交付；当前展示规则以最后的“不足3分钟默认隐藏”续改为准。

## 静态定位

原列表持会议锁逐场调用完整详情读取；每次读取重新清理全目录，并在任务操作锁内遍历全部回执，列表最后才取30场。请求成本随会议数量重复放大，外部任务写入也会阻塞列表。单场损坏可能导致整表失败。列表后的自动题名扫描也同步占用HTTP响应路径。

安卓列表、详情和纪要读取此前共用实时处理的10秒总期限。切换首页、会话和记忆会重复发请求，会后结果同步还独立每20秒读取同一列表；页面缺少列表/打开会议的等待截止。以上为源码证据，不是已复现并统计的生产失败率。

## 实现

- 后端列表只做一次目录清理和一次原始档案扫描，任务回执从原子文件读取一次，不等待外部发送持有的操作锁；详情和实际写入继续核对原来源。单场/回执损坏隔离，并明确部分读取。
- 现有自动题名保留原触发范围，扫描移至后台，最多一个在途扫描；扫描错误不再影响列表回包。既有源指纹、最终落盘锁和重复调用保护保留。不能将读取列表描述为绝对不触发模型。
- 安卓三类历史只读GET使用独立20秒总预算，临时网络故障及408/429/500/502/503/504最多重读一次，重读仍计入同一预算；权限、来源及其他永久错误不重试。同路径同身份仅共享在途读取，各消费者取得独立JSON，完成后不缓存正文。历史写请求不因此自动重发。
- H5合并重复页面读取，列表和打开会议25秒停止等待；过时请求、取消、删除或跨服务回包不能复活旧页面。手动和后台读取均处理明确权限失效；列表失败不继续使用旧条目作为当前结果。部分档案或任务回执读取失败有独立提示与重新读取入口。

## 空记录标准

默认收起需要同时满足：明确结束且时间可核对、ASR结束为acknowledged且无错误、没有包含文字/数字的原话、纪要处理已完成且明确无实质内容、没有人工内容/议程/项目/任务/独立摘要/短依据，以及完整归档证明原音实际为0字节、没有未同步定稿或ASR文字。必要的握手/结束日志不当作发言；未知或过大日志保守保留。

有原音但未识别出文字、未上传完、ASR失败/取消、仍在进行、纪要处理中/失败、资产未知的0句会议继续显示。完整原文自然到期也不视为空记录，独立确认结果沿原规则保留。短句、没有任务/决定、模型判为寒暄均不成为本次删除标准。原文已有的折叠与查看全部保持，未删除任何原始业务数据。

这些标准刻意保守，因此不是所有0句条目都会消失。旧档缺少足够资产证据时继续保留，不从缺字段推断没有录音。

## 接口与页面

`GET /v1/meetings?limit=30&include_empty=0` 默认先过滤再截取30场，避免空记录挤掉更早有效会议。`include_empty=1` 为最近30场含空记录。内部项目完整索引不套用户列表过滤，现有搜索范围不扩大。

响应保留 `count`（当前过滤范围总数），提供 `total_count`、`hidden_empty_count`、`include_empty`、`unreadable_count`、`unreadable_operations_count`、`partial`。每行增加 `effective_utterance_count`、`retained_summary_count`、`history_visibility:{hidden_by_default,reason,status}`。旧接口没有新字段时客户端保守显示。

原生 `history.list` 增加可选 `includeEmpty`，默认false，经MainActivity和Engine传给HTTP接口。会话与记忆的会议列表共用显式“查看全部记录／隐藏空记录”选择；首页始终跳过已确证空记录。自动会后结果同步沿用当前选择，并退休切换前的列表请求。文字缺失、转写未完整结束和全文到期分别显示。
