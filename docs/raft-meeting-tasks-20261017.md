# 会议确认任务 → a1234 → 原任务回流

用户要求手机 Oops 核对会议任务后直接派给 a1234，执行回复与成果回到对应任务。当前交付以生产后端和主版 `com.oops.app` 的实际安装为准；状态在本文末尾记录。

## 手机操作

- 三场核对站候选：在任务页打开「在 App 内核对」，保存本人已确认的待办，再点「派给 a1234 / 查看执行结果」。修改中的答案须先保存。
- App 会后事项：在会后核对中确认待办，或从任务/项目中的「App 会后已确认待办」打开同一入口。
- 派工页重新读取当前事项、原话依据及本人身份，显示最小任务简报与原负责人。执行 Agent 默认选择当前群内已核实的 a1234；来源核对和本次发送均需显式勾选。整场会议、录音和其他资料不会自动附入。
- 同一入口返回该原任务的协作任务、群线程、回复与人工成果核对注记。已绑定线程前台约每 9 秒只读更新，编辑、核对、隐藏或离开时暂停。人工成果注记保留原回复编号及内容哈希，不自动完成业务任务。

## 来源与身份

`GET /v1/raft/source` 和 `/v1/raft/source/links` 沿用原服务凭据及原生 `X-Oops-User-Token`，只接受两种固定来源：

```json
{"kind":"meeting_item","session_id":"实际会话ID","item_id":"mi-…","fingerprint":"实际64位指纹"}
{"kind":"label_review","source_meeting_id":"0235|0236|0238","item_id":"ai-…","fingerprint":"实际64位指纹"}
```

核对站沿用本人实际飞书账号对应的答案，不借同伴确认。App 会后事项旧 `review.by` 来自本机称呼，只保留历史意义；本次独立派工确认以服务端验证的个人会话、账号绑定和实际会议归属为准，不改写原 `item_reviews`。旧会议未核实归属不能自动认领。

来源读取合同有效 5 分钟，由原后端来源签名服务签名。`task.create` 须提供 `task_ref`、当前 `source_contract`、`source_confirm:true` 和逐次 `confirm:true`，独立记录本次本人确认。数据库只保存来源定位、账号绑定、版本与哈希，不保存手机会话令牌、OAuth 凭据或整份会议原文。供应商凭据继续只在可信 Mac 的私人配置。

核对站暂没有单事项单调版本，本轮保守冻结本人的会议核对版本；核对同场另一事项后，旧派工也可能要求重新核对。App 会后事项保留原单事项版本与来源撤回保护。

同版来源与本人只允许一个协作任务，一个协作任务只允许一个根线程；补充在原线程逐次确认。未知送达只查询原任务/发送编号，不能换编号重发。来源修订、删除、到期、撤回、合并或账号变更后停止后续发送，并清除可见旧正文和回复；真实任务编号、送达事实与原历史保留。临时读取失败停止发送并撤下正文，恢复后仍查询原对象。

结果绑定保存于原 Raft 独立 SQLite 库：来源对象 → `raft-task:` ID → handoff/outbox → 实际 Raft 根/线程 → 原回复及核对注记。既有会议、各人的答案、飞书正式任务、录音、Mac 执行器和手写协作历史保留。本轮回流不自动创建或更新飞书任务状态。
