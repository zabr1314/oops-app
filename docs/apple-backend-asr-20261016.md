# Apple音频接入Oops主版转写

用户明确要求将手表音频改接Oops现有转写链路。本记录取代Apple业务首版“新场使用Apple本机识别”的安排；原场的实际结果和失败历史保留，不把新代码接入当作真机通过。

## 处理路径

Watch真实录音 → iPhone接收并转换16kHz/mono/s16le → 已配对的手机专用网关 → 主版火山bigmodel_async识别 → 既有`/v1/utterances`语句处理 → 原会议sync、原音归档 → 原会后处理与minutes读取。

- 主版Android实际直连火山WebSocket，8787没有通用主ASR音频HTTP入口。因此手机网关新增受限适配，复用仓库已有`asr_words_probe.py`的协议和生命周期，而不是另选识别服务。
- 与主版相同的二遍识别、ITN、标点、增量定稿与热词；仅真实definite句子进入后续处理。一次空EOS后须收到provider末包才确认完整，socket关闭不算结束成功。
- 手表继续约29秒分段传输，每段单独WS；与主版连续WS的跨段上下文不同。当前接通相同引擎、参数、语句和会后接口，不宣称输出逐字相同或连续实时流验收通过。
- 真实句子和词时间只加一次原分段起点，保留原文。ASR的说话人编号不当真人身份，本轮不自动调用声纹登记/识别或创建任务。
- iPhone就绪看已鉴权的服务能力，不再要求Apple语音识别权限，也不在云端失败时静默回退Apple识别。

## 受限异步接口

相对既有`/oops-meeting/apple-mobile`前缀：

| 请求 | 行为 |
| --- | --- |
| GET `/capabilities` | 已鉴权ASR引擎、版本、配置就绪与分段上限，不返回供应商凭据 |
| PUT `/sessions/{id}/asr/chunks/{seq}?start_ms=N&end_ms=N` | 实际PCM、大小/哈希/时间核对，先持久登记再返回202 |
| GET `/sessions/{id}/asr/chunks/{seq}` | 原请求与分段绑定的真实ASR状态、结束回执、句/词及独立语句处理状态 |
| GET `/requests/{id}` | 原登记请求回执；202与ASR完成分开报告 |

仅本grant新建的canonical会话可用。相同会话/分段冻结音频哈希和起止时间，即使换请求ID也不能重复付费启动；未知结果只查原job。queued可恢复，已claim的running在进程重启后变unknown，不自动重放。临时PCM及转写继承原音/全文较短期限、原grant与当前来源可用性；撤回、删除或到期不返回旧结果。ASR结果先保存，再独立处理Jev，不能因后续处理失败而重复ASR。

## 旧记录和真实核对

已同步的Apple转写标为旧来源，保留原句、请求回执及冻结的incomplete，不默默替换或重复追加一套新句。未向后端提交文字的草稿才能按新链路继续。DEBUG hold在实际云ASR之前拦住音频提交。

本轮核对来源为用户先前已确认30/30天、已排除公开蜘蛛页的89.392秒会话中的第3段（57.848–86.772秒）。仅独立提交一次ASR/已有Jev处理并读回状态，不改原场文字、结束状态或纪要，不自动新开麦克风。

## 本轮实际结果

- 8799独立服务已升级，备份为`/var/backups/oops-apple-mobile/ASR_20261016T111705845505Z`。升级前后主后端PID与所有Python源码哈希一致，原后端未重启。
- 新版Phone/Watch完成真机签名构建、严格签名核对、覆盖安装和启动。iPhone鉴权能力为`volc-bigmodel-async/ready`；S9收到同grant的后端就绪状态。
- 指定28.924秒片段925,568字节PCM实际提交一次。服务器和iPhone均读回同会话、请求、PCM哈希的`ready`、`provider_closure=acknowledged`，4句152字、136项真实词时间；结果绝对时间57.848–86.770秒。
- 四句均由已有`/v1/utterances`返回`jev-1.13.0`，四项处理为ready。数据库该会话/序号只有一个ASR job，处理后临时PCM已清除。未将分类结果当作人工准确率验收。
- 首次iPhone查询遇到一次TLS错误（-1200）；重新启动后仅GET同任务即取回完整结果，没有再PUT或重复识别。旧89.392秒场仍是原本20字和冻结的`incomplete`，未写回这次152字或替换旧纪要。
- 新版已将旧35段、995.380秒场的原音补归档完成，手机`audioUploaded=true`且无待核对写入回执；旧108字保留，另27段旧文字尚未完整处理，不自动重新转写。USB恢复只调用现有持久回执核对，只有原请求明确未登记时才允许相同内容/ID继续保存，不生成替代ASR请求。
- 本机及Mac mini的临时供应商配置副本已删除，服务器暂存副本已清除；运行配置保留0600。App不包含供应商凭据。

本轮完成最小真机签名构建、实际片段联调与必要静态核对，受保护运行时检查28项通过；未运行自动化测试。新的整场录音→收尾sync→实质纪要、长时间后台和连续WebSocket尚未整场验收。当前约29秒分段与主版连续WS的跨段上下文差异仍保留。

## 部署范围

仅升级既有8799手机专用服务，代码在`/opt/oops/apple-mobile`，私有火山配置在`/var/lib/oops-apple-mobile/asr-config.json`，凭据来自与主版构建相同的可信配置，权限0600；App与Watch均不持供应商密钥。新增ASR表保持原grant/session/request表兼容。`upgrade-asr.py`备份代码、unit与私有数据库快照，仅回滚本轮代码/配置，不自动覆盖运行数据库。

独立依赖固定[websocket-client 1.9.2](https://pypi.org/project/websocket-client/1.9.2/)，按官方wheel SHA-256核对后放入手机服务独立vendor目录；不改原主后端Python环境。保留原主后端源码、配置、会话数据、发送确认保护和原服务运行。新服务升级前后分别核对主后端PID、源码哈希和保存合同能力。

本轮没有新建另一套纪要执行器或MiMo主转写，也没有授权飞书外发。部署与真实片段回执仅保存在忽略的`build/apple-platforms/backend-asr-*.json`，只含核对元数据，不能用片段完成代替整场验收。
