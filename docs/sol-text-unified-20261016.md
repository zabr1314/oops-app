## 模型与失败语义

新增 `scripts/sol_text.py`，复用服务器现有私人 `OOPS_MINUTES_CONFIG` 配置和 HTTPS 客户端，要求模型为 `gpt-6.1-sol`。不把凭据放入 Android、H5、Git 或回包。显式配置无效或不是 Sol 会报错；未配置的旧环境继续原路由，健康回包明确标为 `legacy`，不能宣称已统一。

已配置 Sol 时，文字调用失败不会悄悄切回 Jev、DeepSeek 或规则并冒充成功。新增健康字段 `text_processing_model`、`text_processing_provider`、`text_highlight_version`。结构化输出校验失败、截断回包或非预期模型均拒绝；客户端没有 HTTP 自动重试。

Sol 的语义选择返回 `prob=null`、`confidence_kind=uncalibrated`。App 对 Sol 召回使用单独的候选分支，不把 null 换成 1，不因缺少概率扩窗重复收费；旧概率服务保持原门槛。提醒只供本人核对，不自动将议程标成已有结论。后台标题、问题扫描及任务清单另以同源请求记录阻断结果未知后的自动重发；不把发送了请求等同于取得有效结果。

实时 tag 缓存包含模型和完整来源指纹（正文、时间、说话人、上下文及校验状态），避免同 ID 改写后复用旧摘要；缓存保留现有五分钟期限。草稿缓存也改为完整输入哈希，避免只比较上下文尾部产生碰撞。这些临时缓存不构成长久的调用账本，也不能代替部署后实际费用和延时观察。

## 高亮与持续使用

模型仅处理当前原话与最多四条上下文。候选摘要最多 280 个 Unicode 字符，证据最多五条且短引用总计最多 280 字符；每条证据绑定原句 ID、全文 SHA-256 和开始/结束时间，必须包含当前句。原话里的命令作为数据处理。

摘要与原话分别保存。短依据必须是原句或按句末标点/换行界定的完整连续句，不能截在逗号或字数上限处伪装完整。条件、否定或转述信息没有保留时先等待核对；无法在短依据预算内表达完整来源时暂不留下候选，不落盘整场全文来补齐。

手机回包后再次核对当前五分钟内仍存在的原话、时间、哈希和引用，原话已变或已移出范围就不新增候选。语义相似和相同文字仅建立待核对关系；不同原句、说话人或条件不自动删除、合并、确认。重复收到同一来源的回包保持幂等。

候选使用原子写入；坏文件明确失败，不能当成空列表覆盖。用户确认或舍弃时先写仅含 ID/哈希的有限处理回执，再移除候选，防迟到回包复活。回执独立存放，不自动迁移旧候选或旧记忆。确认保存沿用稳定 saved ID，失败后仍提示核对已有片段与重试，不冒报成功。

这不是准确率验收：当前四句上下文仍可能不足，模型仍可能误提、漏提或摘要不当，词面校验也可能保守漏提。持续使用的真实效果、吞吐和延时尚未测量。

## 长会与硬件
