# History 读取超时续修

用户报告“历史服务读取超时／正在自动重连／历史内容已清除／未载入私有历史”。本轮在线上原History标签实际复现，修复仍更新原链接，不使用本地源码页或示例替代真实数据。

## 诊断

清除提示来自原私有内容保护：详情请求超过15秒后撤下无法核对的正文，仅保留会议ID和播放意图。后端会议文件未因此删除。本轮保留该保护，不通过延长超时、隐藏错误或继续展示失效内容掩盖问题。

确认三项重复开销：已结束会议也带有source.live对象，前端因此错误地每5秒完整核对；同一GET在初始化、聚焦和后台核对时可能重叠；详情鉴权为判定单场自动公开资格，会先完整扫描其他会议。列表则每场重复读取同一份纪要状态。

一次实际诊断中，本机服务列表GET约1580ms、337句详情约2481ms，公网详情约2963ms；History进程当时累计CPU为64.7%，当时公网仍可读取。上述仅为本次读取观察，不足以排除所有间歇网络因素，也不是基准或固定耗时承诺。

## 改动

- 详情鉴权仅检查指定会议的自动公开资格，沿用相同的正式云保存、来源、起点、删除、到期、排除及回放来源规则。固定范围和个人会话仍每请求核对；列表及重新分析仍使用原完整范围。
- 单次列表请求内只读取一次纪要状态并复用；详情仍重新读取。没有跨请求缓存正文或权限，也未更改纪要质量投影及原过程记录。
- 纯GET仅在同一路径、相同条件请求头和同一本页会话代的请求仍在途时合并。完成或失败立即移除，调用者取得独立正文对象与ETag；无正文恢复请求不与304核对共享，POST/DELETE不合并并清空旧在途索引。
- 活动会议保留5秒核对，已结束会议回到原30秒及聚焦/重新显示核对；新会议列表发现继续保留。15秒单次读取截止、超时清空、自动重连、迟到回包及来源失效保护不变。
