# 会议待核对直接发到 Raft

用户要求在任务页的会议待核对卡片隐藏对话，使用直接按钮把任务交到 Raft 完成。此轮承接真实 Android 主版与现有生产后端。

## 操作

会议候选卡片显示任务标题、简述、来源及人工核对状态，原对话不在卡片展示。主按钮为「发到 Raft」。进入紧凑派工页后只读核对当前简报与固定 a1234，一次明确确认后创建/读取该来源的协作任务，并登记独立线程派工；没有长对话、成员选择表、手写派工表或重复确认勾选。

尚未确认的当前任务候选也可显式交办。它仍显示「候选未确认」，服务端在发送根消息与续发时加入固定说明：先在原线程澄清范围、负责人和时间，再执行；进展和成果回复该线程。模型建议负责人只作为未核对建议，不能代替人工负责人。此动作不保存、覆盖任何原核对答案或自动完成业务任务。

已有任务显示发送状态、回复与人工成果数量，并提供原 Raft 线程入口。执行回复和成果继续归属对应来源任务，紧凑页不展示聊天内容。原完整核对及成果记录入口保留。

## 后端

`source.read` / `source.links` 仅新增固定 `mode=delegate`，默认模式维持原确认事项合同。已经确认的事项即使由 delegate 读取也使用原合同域和来源版本，不能借切换模式制造重复任务。

候选采用独立签名域 `oops-raft-candidate.v1`、已签名的 `candidate_state={review_status:unreviewed,responsibility:unverified}` 和 `candidate_collaboration` 类型。来源仍须为当前可用 task；排除、合并、类别变化、旧核对、来源撤回等拒绝交办。读取合同5分钟有效，实际本人飞书身份、原会议权限与当前来源版本在保存、派工与 worker 网络发送前复核。候选返回 `source_confirmed_at=null`，仅独立保存此次 `dispatch_confirmed_at`。

相同来源定位与同本人账号的旧根消息/续发若 unknown、dispatching、preparing 或送达事实无法核对，禁止跨版本新建任务或根消息；只允许查询/恢复原请求。来源或群权限失效时保留原任务、请求编号和传输回执，遮蔽旧正文、回复与继续发送许可。已知送达的旧版保留原线程；当前确实新核对版本另派前明确告知旧版已发送。
