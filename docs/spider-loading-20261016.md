# 蜘蛛页来源与读取优化（2026-10-16）

本轮基于 main `981423c`，修正实际读取中发现的分析来源、部署配置和大正文重复传输。已发布到原线上历史页，下面区分本地验证与生产回读。

## 实现

- `funnel.js` / `funnel-after.js` 根据已存 `post.generation.evidence` 区分新生成、复用旧纪要与证据缺失。全链路不再显示“只调用 Jev”；Jev 请求数明确标为 Jev，不当作所有模型的总调用数。展示不发起模型、ASR 或外部操作。
- 当前部署配置单独放在 `deployed_pipeline`，不覆盖历史 `pipeline`。配置先到、正文后到或定时配置刷新都更新会中/会后标签，不重建播放进度。`asr_review_supported=false` 与读取失败分别显示。
- 历史入口不再预载示例。开始读取另一场会议时清空旧正文、画布和会后结果，保留请求版本防护。
- 网关响应 JSON 去掉非必要空白；客户端接受 gzip 时以 level 4 压缩较大的 JSON/静态文本响应。保留 `no-store`、同源限制及原读取范围。
- 正文接口在每次重新鉴权、读取并验证源头之后计算弱 ETag。已载入内容未变时返回无正文的 304；前端保留当前播放位置。源头修订仍返回新正文，权限/到期失败仍清空旧内容。校验值忽略每次读取都会变化的 `pipeline.verified_at`，其他字段仍参与校验。没有新增持久正文缓存。
