## 事项投票匹配

`scripts/minutes_vote.py` 不再仅因共享原句编号就把两条结果视为同一事项。现改为比较具体文案；共同来源允许正常中文改写，但不能替代事项内容的一致性。明确动作或否定冲突保持分开。

候选优先加入内容最相近的组，并须与组内全部结果相容，避免 A 与 B 接近、B 与 C 接近就把互不相符的 A／C 连成一组。组内仍只允许每份生成贡献一票，代表文案按实际相似程度选择；来源编号合并、负责人提示、主次优先级及日程时间／时长冲突处理沿用原逻辑。

静态核对覆盖了原问题的分组推演：同一句含 A、B，三份为 `[A,B]`、`[B]`、`[B]` 时，后两份 B 优先匹配原 B 组，共享原句不再使它们直接并入 A；正常 App／P0 文案改写和同时间路演标题变体保留匹配空间。此处没有执行测试，也不把本地文字相似度当作通用语义等价证明；歧义较大的改写可能保持分开。
