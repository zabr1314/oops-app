## 本轮修复

### 问题03：带来源任务的服务端核验

复用已有草稿、操作日志、外部创建防重及读回。服务端签发来源合同，绑定本场、所选原话、说话人、核对信息及任务引用的上下文；不信任客户端自行计算的哈希。来源签名私钥只在服务私有状态目录，App 冻结并回传合同，不持有私钥。

提交前及真正外部写入前重新读取当前来源。修改、删除、撤回、修改后再撤销，均不能让旧合同复活；追加不相关原话不误撤回旧任务。自然全文到期后，仅允许当前有效、独立确认的短依据接续，不恢复全文。已经创建的同一操作保留原回执；无会议来源的手工任务仍可用。

只有服务端证明本次尚未外部写入的来源冲突才返回确定失败，App 提供重新核对原话入口。此前外部创建结果未知的操作保留 `pending/source_blocked`，停止再次写入并显示真实原因，不误报未创建或重新生成操作编号。

### 问题04：原生任务板及草稿联动

请求、轮询、快照和事件同时绑定会话、服务地址、服务代次及本机来源代次。切换服务、相关原话／身份／核对信息变化、实际归档到期时撤回旧结果并取消旧轮询；迟到响应不能覆盖当前内容。局部修订只撤回依赖该来源及上下文的未提交草稿，不影响不相关任务或已提交回执。

普通正式会议的五分钟现场字幕滚窗不等于归档到期。自然到期后任务板与显式原话入口仅使用独立确认的有效短依据，保持原有 Task ID 与来源，不将完整文字重新写回本地索引。H5 同步处理局部撤回、来源核验、确定冲突与未知结果查询。

### 问题05：录音豆 SDK 冗余副本

本机没有真实 Soundcore SDK 和设备，现有可核对接口没有关闭本地副本的选项。因此真实录音豆的日常模式在 SDK 初始化／扫描前明确拒绝，提示手动选择手机麦克风；不静默换音源、不假称满足五分钟临时策略。手机麦克风及录音豆模拟不受影响。

正式会议继续沿用现有 SessionRecorder 归档；SDK 冗余副本改到本场受管临时目录，断开确认后清除。实际原音期限到达时先停传输；清理失败阻止新会话绕过。进程重启只清新命名空间残留，旧 `filesDir/bean` 历史数据不追溯删除，设备本体录音不属于本轮 App 副本管理。迟到回调、重复停止和音源启动失败均有保护。

公开网站保持隔离示例，不加入真实团队音频、标注数据、共享服务凭据或 Mac 执行器凭据。安卓流程预览复制当前同一份 H5，新增“任务依据尚未核验”“任务依据已变化”情境。主 App、既有真实页面总览和交互画板保留；本轮未改 React 页面布局，不把后台修复包装成新增真实服务接通。

## 仍未完成的 P0

- 问题01：公开 React App 尚未接通真实用户数据；真实日常短依据只保存在本地时不能签发服务端来源合同，因此当前不能从这种临时来源创建真实飞书任务。明确保留候选或在飞书手工创建；反复读取不能解决，也不能恢复整场日常同步来绕过保存策略。独立短依据后端接入与同一用户数据贯通需继续实施。
- 问题02：用户、项目、会议、任务的服务端权限隔离及本人飞书授权仍缺。来源签名不是登录权限，不能因本轮签名就标记账户体系完成。
- 问题09：真人会议准确率及真实设备验收仍待执行。AI 辅助标注、纯逻辑回归、浏览器隔离示例均不能替代内容质量验收。

## 部署及验收交接

本轮没有部署香港真实后端、构建／安装完整 APK 或接入真实录音豆。SSH 严格可信检查在连接前停止（现有 Mac 未保存目标主机的可信 Ed25519 key），没有跳过检查。当前 JDK 为 8，缺 JDK17／Android SDK 和真实 Soundcore AAR；纯 JVM 与假 SDK 控制流编译不能替代完整 Android 编译。

真实发布须协调后端与 APK 合同升级：后端至少同时发布 `local_backend.py`、`meeting_features.py`、新增 `action_sources.py` 及本轮涉及的 `task_board.py`；沿用现有服务配置和私有状态。保留 `operations/.action-source-key`（0600），不复制到 App、仓库或公开站。升级脚本必须包含新导入依赖，不可只替换单个后端文件。旧草稿缺新合同须重新读取，不静默降级；旧已创建操作仍可查询历史回执。

需要同伴配合：提供已核验的服务器部署入口／SSH 主机指纹，在已有 Android／SDK 环境编译安装新版；之后用一场新真实会议验证来源修订、切服务迟到响应、断网恢复、到期后的有效短依据及实际任务回执。拿到录音豆后验证 SDK 实际关闭文件和清理行为。测试数量及 GitHub／网站／飞书同步结果以本轮最终交付记录为准。
