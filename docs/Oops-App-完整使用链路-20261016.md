# Oops App 完整使用链路

适用版本：2026年10月16日 Redmi 2311DRK48C 上已安装的 Android App，包名 com.oops.app，版本 0.1.0，安装更新时间为手机记录的10月15日20:44。本文用于本人及团队试用、操作交接和功能核对。

主链路是：选择身份与连接 → 选择日常聆听或正式会议 → 看原话和找回片段 → 核对重点与负责人 → 单独保存记忆或创建正式任务 → 核对发送纪要 → 在下次会议继续复用。录音、内容核对、负责人确认、任务创建和外部发送各有独立状态。

本文以实际手机页面为准。当前安装版底部是「首页、会话、中央录音键、任务、记忆」，「设置」在首页右上角；会话详情实际有三个分栏。网页原型里的五导航、四分栏和助手成果流程不能直接当作手机已实现能力。

## 1 开始前先选对入口

| 入口 | 主要用途 | 当前手机上的位置 |
| --- | --- | --- |
| 首页 | 开始记录、查看私人重点、问已有记录、接续会话 | 底部首页 |
| 会话 | 当前记录、往期会议、原文、会后核对 | 底部会话 |
| 录音键 | 开始记录；录音中进入结束确认 | 底部中央圆形按钮 |
| 任务 | 待核对候选、我的任务、团队正式任务 | 底部任务 |
| 记忆 | 日常私人重点、人物声纹、项目决定与会议 | 底部记忆 |
| 设置 | 本机身份、个人飞书、音源、连接、设备、隐私 | 首页右上角 |

系统返回键先关闭底部面板，再返回上层页面；已经在首页时会将 App 放到后台。查看原文、核对事项、选择项目等面板可以返回取消。取消选择不等于已经保存。

### 首次使用的准备

1. 从首页右上角进入设置，先阅读「隐私、保存与共享」，分清日常临时内容和正式会议归档。
2. 检查「当前身份」。本机显示名方便界面展示，真实「我的任务」和纪要发送以绑定的个人飞书账号为准，不能只改显示名就认领他人的数据。
3. 打开「我的飞书」，核对绑定账号及文档创建、收件人权限设置、纪要通知等已授权能力。未绑定时进入飞书官方授权，确认后返回并刷新状态。
4. 打开「收音、唤醒与提醒偏好」，正常使用选择「手机麦克风」；开发调试才选测试 WAV、Mac 收音或录音豆模拟。
5. 在系统提示中授予麦克风权限，允许录音通知。Redmi 长时间收音还需检查系统电池和后台限制。
6. 真实服务模式下，后端地址和访问凭据由受信任的维护者配置。Mock 只模拟本机流程，不能用来证明真实同步、任务或发送成功。

本轮使用已有安装和授权，没有清空 App 重走首次安装，也没有重新授权或覆盖任何人的声纹。

## 2 日常临时聆听

适用场景是随时交流、临时想法、想找回刚说的话。完整原音和临时全文只保留最近五分钟，停止时清除；私人候选重点与本人单独保存的短内容另行处理。即时识别可能由云端 ASR 处理，不能理解为音频完全不上云。

### 开始和现场查看

1. 点击首页「开始记录」或底部中央录音键。
2. 在「选择记录方式」里保留默认「日常临时聆听」，阅读说明后点「开始本次记录」。
3. 进入会话的当前记录。现场有「现场、原文、行动」三个分栏；当前停留的分栏可能延续上一次选择。
4. 查看是否真正收到声音：记录计时、音量和收音状态应更新；识别连接成功和出现定稿原文是两件事。一直没有文字时，检查音源、麦克风和识别连接。
5. 「原文」逐句展示定稿、时间和身份状态。尚未核实的说话人保持未识别或待确认，不能凭一个名字认定已经取得声音许可。
6. 「现场」查看最近原话、候选发现、议程和会议提醒；「行动」查看本场候选或已有清单，不把候选当作正式任务。

离开当前会话后仍有紧凑记录条，可返回现场、找回刚才或展开控制。中央录音键在录音时变为结束入口。当前真机没有验证到普通录音的暂停按钮；设备示例里的「暂停」不会暂停真实麦克风。

### 找回最近五分钟

1. 点「找回最近5分钟」或活动记录条里的找回图标。
2. 等待原话卡片。多个接近结果时先选中正确的一条。
3. 阅读原文和时间范围，需要上下文时点「＋前一句」「＋后一句」，可还原范围。
4. 点「回听原声」检查所选片段，播放时按钮变为停止。原音超窗或不可用时按实际提示处理。
5. 需要长期留下才点「保存」；需要变成行动时点「生成行动」，继续核对草稿。仅打开、回听或关闭卡片不会创建飞书任务。
6. 没找到时换一种问法或从原文定位。五分钟外已清除的日常原音不能承诺恢复。

### 结束以及核对私人重点

1. 点中央结束键或现场「结束当前记录」，阅读「结束日常聆听」确认。
2. 点「继续记录」可取消结束。当前安装版只是取消结束面板，录音继续；不要套用网页原型的结束快照或暂停规则。
3. 确定结束时点「结束记录」。等待「日常聆听已结束」，检查留下数量和临时原音、全文的清理回执。
4. 逐条看候选。需要保留时点「核对并保存」，可改写短内容，核对后明确勾选确认，再保存为私人记忆。
5. 不要的候选点「舍弃」。没有勾选确认时，保存会被拦截。
6. 稍后从首页或记忆中的「日常聆听留下的重点」重新进入；按每次聆听查看，避免混淆不同场次。

候选数量是当前剩余待核对数量；结束回执中的数量记录结束当时留下了多少。确认或舍弃后两者不同属于正常情况。保存私人记忆不自动创建任务、关联身份或共享。

## 3 正式会议

适用场景是需要事后查看原文、回听录音、整理会后事项和明确交付的会议。当前规则要求本次明确云保存，原音和全文分别选择7、30或90天，默认30天；旧会议沿用原规则。

### 开会前

1. 点「开始记录」，切换「正式会议」。
2. 分别选择「原始录音保留」和「完整文字保留」期限。
3. 明确勾选将本次正式会议原音与完整文字保存到云端，再点开始。未勾选会提示「请明确选择本次云端保存」。
4. 进入现场后按需打开「本次议程」：填写目标，每行一个议题，可加分钟数；总时长和单项时长为1至480分钟，最多20项。
5. 需要项目上下文时选择所属项目。不要求先创建团队门户或切团队空间才能开始记录。

### 从日常转成会议

1. 在正在进行的日常记录「现场」里点「从现在转为正式会议」。
2. 如果先前有重要片段，先选择刚才的片段并单独保存。
3. 再选择正式会议的原音与全文期限，并勾选云保存。
4. 确认后从切换时新建正式会议；之前缓冲不会自动并入完整会议归档。Android 首版不复制之前缓冲。

### 会中与结束

「现场」看当前议题、最近原话、候选发现与提醒；「原文」检查说话人和具体句子；「行动」查看候选及实时清单。提醒可看依据并反馈有用或不准，议题覆盖不等于已经形成决定。

点结束并确认后，还需要等待最后定稿、结束同步及录音上传。结束记录、文字可读、原声可回听、AI纪要可用分别成立；任一环节尚未完成时按真实状态显示，不能因为按钮已结束就认为全部完成。

本轮验证了正式会议的保存选择与未确认拦截，复用了已有正式会议检查后半程；没有新建云会议，也没有执行7天或30天的长期到期验收。

## 4 往期会话和原文

1. 进入「会话」，优先看当前记录和待核对会议，其次是已保存会议。
2. 搜索会议名称或项目，找到会议后打开。私人日常重点和已保存片段使用各自入口，不伪装成完整日常会议档案。
3. 「概览」查看主题、会后事项、讨论要点、提醒、所属项目和独立保留结果。
4. 「原文」按说话人筛选或搜索关键词；有收起段落时点「查看全部原文」。折叠不等于删除。
5. 点某句的播放键从服务器回听。通常需要录音已经上传且仍在期限内；本地缓存与服务器存档是不同来源。
6. 点原文句子打开「这句是谁说的」，可以选择成员、其他人、多人同时说或听不清。实际保存会影响团队服务器记录，本轮只查看并取消，没有代改真实身份。
7. 「行动」将待核对与已确认的会后待办分开，并提供查看全部任务入口。

当前手机详情是「概览、原文、行动」三个分栏，活动记录则为「现场、原文、行动」。本轮不把网页独立「资料」分栏写成手机已有功能。

读取失败应保留真实原因并使用重试入口。全文已经到期时不能用旧摘要冒充原文；原声不可用时不能承诺还能完整回听。

## 5 会后核对

核对的目标是把自动整理的候选变成本人明确确认的事项。逐句分类、整场纪要、会后事项和人工负责人不是同一份答案。

1. 在概览点「开始 / 继续核对」，或点某条会后事项直接进入。
2. 阅读事项标题、类别、截止信息和「依据原话」，必要时回听。
3. 是真实事项时点确认；不是事项时排除；不确定时跳过，稍后回来。
4. 文案或类别不准时点「改写」，可改类别、标题及截止。取消返回不保存；「保存并确认」会写入核对结果。
5. 对待办单独选择真实负责人。「大家」是集体责任线索，不能冒充某个自然人的唯一指派。未明确的截止不要补成猜测日期。
6. 重复事项可以合并；确认后仍可改写或撤回确认。来源失效的旧事项只读，不能继续确认。
7. 对已确认待办，需要正式执行时再点「整理成飞书任务」。确认内容本身不会创建外部任务。

保存核对结果需要服务器回执后才推进；失败保留选择并重试。来源变化要重读当前依据，不能拿旧确认继续执行。说话人姓名核对与负责人确认分别操作，不能因为一句话由某人说出，就认定一定由其负责。

本轮打开了真实6项会后事项及原话，检查了改写和取消；没有替用户确认、排除或分配真实事项，因此没有声称核对写入已经复验通过。

## 6 任务从候选到正式执行

任务页当前有「待核对、我的任务、团队任务」三个入口。每个入口内都要区分会议候选与飞书正式任务，候选可搜索并按核对状态筛选，正式任务有独立业务状态筛选。

### 阅读和筛选

1. 「待核对」能看见未分配候选。核对站候选和 App 会后已确认待办分组显示，不复制某人的标注成为全员确认。
2. 「我的任务」读取绑定的个人飞书身份，只纳入人工明确归本人且无归属分歧的候选；正式任务按真实个人账号读取。
3. 「团队任务」查看当前有权读取的团队任务。现有服务权限范围不等于完整的多租户账号隔离已经验收。
4. 搜索任务、原话或会议；候选可筛「待核对、内容已确认、有分歧、已排除或合并、来源已失效」等。
5. 展开候选可以查看原话和各人的核对答案；需要继续标注时进入原核对站，返回 App 后重新读取。

### 创建飞书正式任务

1. 先在会后核对中确认事项和负责人，再点「整理成飞书任务」，复用已确认内容生成草稿。
2. 核对负责人、具体事项、截止、交付要求和引用原话。负责人、说话人、任务提出人分别看待。
3. 只有明确点击「确认创建飞书任务」才发起写入，保存片段和打开草稿都不是创建成功。
4. 等待创建及回读结果，成功后查看飞书任务链接，并回任务页刷新正式任务状态。
5. 如果响应丢失或状态未知，查询原操作；不能换新操作号反复创建。明确失败时遵循同一操作的恢复提示。
6. 来源被修改或撤回后，未执行的旧草稿需要重新核对；已有外部尝试但结果未知时继续查询，不重新发送。

本轮正式任务为0，没有为了试用制造一条真实飞书任务。任务在飞书的推进、验收、完成及 App 回读完成状态没有用空列表代替验证。

### 工作助手

研究、报告、PPT 和日程等已有服务能力与飞书入口应沿用现有执行链路。当前手机没有在本轮验证到完整的 App 提交、job状态、成果版本回流链路；不能把网页的助手准备、PPT预览或模拟回执写成 Android 已接通。

助手产出不自动等于任务业务完成。真实结果要绑定任务、空间、唯一请求和来源，使用可信回包里的链接；生成失败先重新核对授权，交付失败恢复同一个结果。本文不要求试用者为了走完整链路启动收费助手。

## 7 核对并发送飞书纪要

这一流程会真实创建文档、设置收件人权限并通知。绑定账号只是连接条件，每份纪要仍需要单独核对。

1. 打开会议概览，点「核对并发送飞书纪要」；会议工具中也有入口。
2. 查看发送账号。账号不符时回「我的飞书」处理，不能用本机显示名替代真实账号。
3. 检查纪要标题与正文，按需要编辑。
4. 明确选择收件人。参会人只是线索，不自动勾选；可按姓名搜索飞书联系人，再核对选中的人。
5. 设置收件人的「仅查看」或「可编辑」权限。
6. 保存本版待发送草稿，再明确勾选已核对正文、收件人与权限，点击确认发送。
7. 等待交付回执。成功后可点「在飞书查看已发送纪要」。
8. 发送中、结果未知或部分交付时，先点「查询原操作结果」。保留原操作记录，不新建一次发送掩盖未知结果。

修改正文、收件人、权限或绑定账号后，需要保存并重新核对。会议记录人未核实、当前本人不匹配或原会议账号不同，应按页面恢复指引处理；重新绑定飞书不会自动认领旧会议。

本轮接手时手机已有一笔等待回执的纪要操作。仅点击查询原操作后显示「发送成功」并出现文档入口，未重新发送，也没有点击新建通知或给他人发送消息。

## 8 长期记忆和下次继续

### 私人重点

首页和记忆的「日常聆听留下的重点」按场次提供待核对和已单独保存的内容。确认保留短内容不恢复完整原音或全文，也不会自动共享。历史场次缺结束时间和清理回执时，页面应明确未记录，不能补造成功状态。

### 会议独立保留

1. 在会议概览点「选择短依据 / 编辑摘要」。
2. 从当前仍可核对的原文里手选必要短依据，一次最多10条，每条最多280字。
3. 可以填写本人核对的摘要，最多2000字；摘要应引用本次选择的依据。
4. 明确勾选独立保留确认，再保存，等待匹配的服务器回执。
5. 普通失败重试相同请求；来源变化则重新读取和核对，不能连续提交旧确认。

完整原文自然到期后，独立有效短依据与确认摘要按各自规则保留；主动修订、删除或撤回来源时仍需检查派生内容的有效性，不把旧成果继续当作当前依据发送。

### 人物和项目

「记忆 → 人物」当前展示声纹成员和录入入口，不是完整社交关系系统。只能把明确核对的身份与相关原话联系起来；声音相似度不等于正确概率，也不推断亲疏或人格。

「记忆 → 项目」查看同一项目里的已确认决定、任务和会议。在具体会议「所属项目」里新建或选择项目；下次会议归同一项目，才有相应历史上下文。未核对决定不会自动变成已确认项目记忆。本轮真实项目列表为空，只检查选择入口，没有为用户新建项目。

## 9 声音身份和设备

### 声纹录入

1. 进入「设置 → 声音身份与许可」，或「记忆 → 人物 → 声纹录入与匹配测试」。
2. 选择正在朗读的本人，阅读并明确同意上传声音用于匹配。
3. 按固定文本单独朗读约30秒，避免旁人讲话和播放录音。
4. 看时长、有效音量和质量结果，再明确保存；替换的是所选成员现有声纹，其他人保留。
5. 用另一段约10秒文本测试匹配，核对真实人名，不把最高相似度直接当作身份真值。
6. 不保存就退出或重录。删除需要单独确认，不替其他人录入或授权。

本轮回读了4位已有成员的30秒声纹状态，只检查页面和许可；没有录入、删除或验证真人识别准确率。

### 录音豆和自动聆听
