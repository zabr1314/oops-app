# 标注页：待核对改为整场事项

用户指出原来的「待核对」是逐句分类的碎片，看完不知道要做什么。本轮把核对对象改成**整场会议的事项**：AI 读完整场原文，整理出待办 / 决定 / 待定，每条附依据原话；人确认、改写、合并、排除或补漏。逐句分类按用户选择收进「全部原话」作为参考和评测，原有答案、盲测和声音身份全部保留。

## 页面

- 顶部三个工作区：**事项**（默认）／全部原话（原「标内容」，内部“待核对”筛选改名“未标注”）／认声音。
- 事项列表按 待核对 / 已确认 / 已排除 筛选；当前事项显示类别、一句话标题、补充、截止（原话提到才有）、“原话里有人认领”提示，以及依据原话（可逐段听、整条连续听、跳到全部原话看上下文）。
- 操作：确认这件事（待办必须先选负责人，AI 不猜）、改写（类别/标题/补充/截止/负责人）、不是事项、和另一件合并、撤回确认、撤销上一步；「补一条漏掉的事」从原话勾选依据句（最多 40 句）新建并直接确认。
- ↑↓ 换一件，空格连续播放依据原话。手机宽度下列表收起。

## 生成（`scripts/label_items.py`）

- 一场会一次请求：整场原子句按 `句ID 时间 原话` 发送，固定盲测句不发送，只标出“此处约 N 秒原话未提供”。提示版本 `items-v1`，模型沿用 `deepseek-flash`，非思考模式、JSON 输出。
- 校验：类别只允许 task/decision/open；证据必须是输入里出现的句ID区间，按可见顺序展开（跳过盲测句），单段 ≤180 秒，重叠段合并；无有效证据的事项丢弃并计数。事项ID与指纹绑定内容和依据原句指纹。
- `items.json` 绑定原话 source_hash 与盲测集合；原话或盲测变化时整份失效（显示“原话已变化”），不会拿旧事项冒充当前结果。
- 费用：`quote` 离线报价（UTF-8 字节上界），`generate` 必须带报价哈希和批准预算；每次请求前先把上界写盘预占。失败或中断不会自动重试，`quote --retry` 只为未完成的场次再报一次价、追加一次尝试，并保留原尝试记录。

本轮实际：首轮在本机后台运行时两场请求被会话结束中断（DeepSeek 侧已收到，缓存命中可证），用户另行批准总上限 ¥0.55 后各重试一次。按回包 tokens 计：0238 ¥0.031、0235 ¥0.047、0236 ¥0.028；两次中断请求未取得回包，按预占上界记 ¥0.270。预占合计 ¥0.377 < ¥0.55，实际账单预计约 ¥0.18。结果：0235 15 条、0236 12 条、0238 13 条，无丢弃。

## 核对存储与接口

核对按人保存在 `item-reviews/<会议>/<姓名>.json`，与 AI 的 `items.json` 分开；沿用标注站的 revision 冲突检测、request_id 幂等和 30 步撤销。AI 事项更新后旧核对标为需重新确认，不自动沿用。

| 接口 | 说明 |
| --- | --- |
| `GET /api/meeting/<id>/items` | 事项、各自依据原话、本人核对状态、计数 `todo/confirmed/rejected`、可选负责人 |
| `POST /api/meeting/<id>/items/review` | `action`: `confirm`（可带 kind/title/detail/due/owner）、`reject`、`merge`（`into`）、`reopen`、`add`（`ids` 依据句）、`undo`；需 `request_id`、`revision`，AI 事项需 `item`+`fingerprint` |
| `GET /clip/<id>/<首句>.wav?until=<末句>` | 依据原话连续片段，≤180 秒 |

`label_items.py export --data DIR` 输出每人确认/排除/合并/未核对的事项，用于计算“漏了几件、多了几件”。

## 接入 App 后端的下一步

`build_request` / `parse_items` 不含存储和预算逻辑，可直接给后端复用：会后整理时对整场原文调用一次，结果按同样的“证据句ID + 指纹”结构存储，App 会后结果页直接展示事项卡片，待办负责人由本人确认。与现有后端任务队列、防重回执的对接按“前后端协作基线”由后端已有接口优先。
