# 转写后提醒判断统一 Sol：接口与边界

日期：2026-10-16。用户明确选择将转写后的文字理解统一使用 `gpt-6.1-sol`；本文件记录其中议题、议程结论及冲突提醒的适配，不把语音识别、声纹或硬件收音替换为文本模型。

## 本模块的接入契约

`scripts/meeting_features.py` 的 `judge_notice(req, reasoner, overlap, history)` 保留原调用位置和参数顺序。统一文字处理器由后端注入；可信对象必须具有 `semantic_only is True`，并提供：

```python
answer, engine = reasoner.choice(payload, task, options)
# answer: {"choice": "options 中确切存在的 key"}
# engine: 实际处理模型标识，本轮统一处理器为 "gpt-6.1-sol"
```

仅对象标记选择语义接口。回包里的 `confidence_kind`、自报 `confidence`、one-hot 或其他概率字段不能改变旧 Jev 路径，也不被当作模型概率。Sol 的 `choice` 必须是本次实际选项的字符串 key；缺失、越界或格式错误直接拒绝，让既有调用层按其规则降级或报错，不从数字置信度推断选择。

Sol 提醒结果保留原来的 `topic` / `resolved` / `conflict` / `with` 字段，新增实际 `choice`；统一返回 `prob=None`、`confidence_kind="uncalibrated"` 和处理器实际 `engine`，不输出拼造的 `probabilities`。议题已有 `unclear`；Sol 的议程结论与冲突选项增加 `unclear` 供证据不足时保留判断，议程此时返回 `resolved=None`。

冲突选项绑定本次当前可见的实际先前原话。Sol 选择具体来源后返回它作为待核对线索，不套用旧 Jev 的 `prob >= .6` 门槛，也不把空概率替换为 1。`none` / `unclear` 都不生成冲突线索。模型没有直接修改原话、决定、负责人、人工答案、任务或会议状态的能力。

## 兼容与未扩大的权限

- 旧 Jev 对象继续校验完整概率字典，议题/结论的原返回结构和冲突 `.6` 阈值保持原样。即使旧回包自带 `confidence_kind="uncalibrated"`，也不能绕过原概率校验。
- 旧服务环境无处理器或旧模型失败后沿用的本地规则仍标为 `engine="rules"`、`prob=None`。当前已配置 Sol 的后端调用失败会明确报错，不用规则冒充成功。规则只保留已有词面议题匹配、明确金额上限冲突及无结论判断，不新增隐式模型回退。
- 语义候选仅供提醒与人工核对。`resolved=True` 是本次文本判断结果，不能直接当作本人确认的结论、议程完成、任务完成或执行许可。App 对空概率的消费须通过显式语义候选分支适配；旧概率门槛不能用假概率维持。
- 本模块不修改流式 ASR、MiMo 会后识别参考、声音身份或声纹校准；声学辅助所用的旧模型不因文字提醒切换而获得额外文字理解职责。
- 实际对外发送、飞书任务创建、长期记忆、会议保存合同和来源有效性校验继续独立。读取提醒、打开页面或模型返回一个选择均不构成这些操作的授权。
- 只对后续真实判断使用新路由；不据此重算历史提醒、旧纪要或改写人工核对记录。
