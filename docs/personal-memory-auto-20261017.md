## 处理与核对

新版 Android 在日常模式的原有逐句 Sol 请求中显式携带 `personal_memory_requested=true`，同一次回包独立返回至多一条 `personal_memory`。身份、偏好、目标、经历与其他日常线索使用五个明确分类；个人候选与普通重点独立，不受普通重点标签限制。正式会议及旧版请求沿用原提示词和输入，不开启个人提取。

只提出完整、有直接原话支持的第一人称自述。上下文最多四句，依据最多五条、合计280字，绑定实际句子ID、时间、全文哈希与来源指纹；不截断半句冒充完整依据，不从他人的事、转述、假设、群体表达或声纹名字推断本人事实。第一人称只证明说话方式，候选始终仍需本人归属核对。

个人页以自动待核对为主。本人可查看建议分类、整理内容和原话短依据，修改分类／标题／正文，并分别明确确认本人归属及内容后保存；也可舍弃。普通日常重点保留辅助入口，手写作为补充；未观察到新协议结果与真正无候选分开展示。

已确认记录写入原有本机私有 `noBackupFilesDir/personal_memories_v1.json`。整理摘要、本人保存内容、短依据及确认版本分别保留，既有手写记录兼容。候选确认、移出队列及处理回执使用同一 AtomicFile 提交，确认和舍弃后防迟到回包复活。保存结果未知时只读取本次候选回执与记忆，不自动换编号重发。

只保留必要短依据，不把日常五分钟全文变为永久档案；候选明确标记全文不可用。本人核对不会授予声音身份、云同步、团队共享、外发或后续模型使用权限。旧的23条日常重点没有额外收费重算，也不为了填满分类而生成个人事实。
