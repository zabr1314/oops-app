# 新会议会后事项自动进入核对站

用户授权将新会议结束后的事项整理接到原核对站，沿用本次团队姓名，负责人最后人工确认。2026-10-13 已部署到原地址 `https://giftedprofessor.xyz/oops-meeting/label/`。此次只部署核对站与衔接服务，不修改或重启主后端，不重新生成旧纪要，不创建飞书任务。

## 流程与入口

1. 已有主后端接收结束的正式会议、完整上传的录音和转录，按原流程生成并保存 AI 纪要。
2. 独立 `oops-label-import.timer` 每次处理结束后约15秒再次检查，只读取已有文件。待上传、待纪要、就绪、失效和失败分别显示；浏览器定期刷新目录，保持当前会议、编辑草稿和负责人选择。
3. 当前纪要的待办、决定、待定及未决问题转换为事项，每条绑定有效原话ID与时间。缺失依据或过长依据丢弃，不补造证据。事项文件与原音镜像先写入，最后原子替换会议清单作为提交标记。
4. 当前有效人工说话人核对随原话进入事项；团队共用已确认姓名，显式本人认领另列原话线索。负责人不预选，事项确认与原话核对独立保存。

仅处理独立授权配置中启用时间之后新建、具有 version1 正式会议云保存合同的记录；日常临时记录、未同意云保存、标为私有或撤回的记录不导入。云保存本身不等于核对站授权，本次用户指令落实为独立 `auto-import-policy.json`，绑定项目后端、既有核对站目录与目的地址。既有18个后端会话加入基线排除，不批量搬运旧会议。启用时间为 `2026-10-13T07:04:00.547214+00:00`。

## 身份、版本与保留

- 本轮五个旧音色组仍独立绑定原来的三场来源。新会议不会套用旧A/B/C字母或加入旧组，避免同字母新人物被误认和旧确认失效；新会议沿用团队姓名名单与来源明确的单句人工核对，未经核对的声音明确待核对。没有开启声纹自动归因或自动负责人开关。
- 说话人、认领线索与负责人各自独立。导入不会把纪要owner提示变成人工负责人，不更改已有负责人、私有答案、身份历史或发送回执。
- 每次读取检查当前原文、纪要版本、上传清单、音频哈希与独立授权。来源修改、纪要换版、音频换版、删除或撤回立即禁用旧证据；下一次定时处理撤回旧镜像。导入音频响应为 `no-store`，避免浏览器24小时缓存绕过撤回检查。
- 镜像沿用源合同的原音/全文独立到期时间，重试不续期。全文到期不再展示转录与旧事项；仅原音到期时可继续核对有效文字，但不能播放。原有人工作答保留为历史，不当作当前有效结果。
- 稳定 session→四位核对站编号映射持久化，重复定时处理不重复创建会议或事项；写入失败显示失败，重启可恢复。源文件损坏或授权丢失时收起旧内容，不能因为上游读取失败继续保留可用旧原音。
