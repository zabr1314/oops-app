## Oops 入口与流程

React 任务列表、任务详情的“交给群协作”、设置中的 Oops 协作群，以及原多人协作入口，承接到同一个群页面。本机私人页面连接本机协作服务后读取真实群与成员；公开网站、画板、试用使用独立内存演示，不访问真实群或令牌。

创建时标题与简报均为空。本人明确填写目标、分工、限制和预期成果，选择当前群内 Agent，再逐次确认发送。Oops 桥接身份不会出现在派工选项中。群内所有成员可能看到线程内容，通知的 Agent 是本次明确选择的参与者。

每份简报对应一个根消息，后续补充绑定实际根消息 UUID，在同一线程推进。可以进入 Raft 群聊或打开已经核实送达的任务线程。回复按确切根线程回收，显示原回复；本人可核对并记录为进展或成果。人工注记保留原回复与哈希，不自动更新任务为完成，不代表交付、验收或授权执行回复中的指令。

从原型任务进入时仅保存 `kind:prototype` 的任务ID、版本和范围以供返回/筛选，不自动复制标题、会议、原话或资料。来源变化时停止关联派工与续发，已结束任务仅查看历史。**当前没有真实业务任务数据库的服务端来源适配**，这个原型返回引用不能作后端来源证明。

## 后端与桥接

新增独立 `collaboration.sqlite3` 保存群快照、冻结交接、续发映射与人工注记，沿用原 `outbox.sqlite3` 的单次发送尝试；原 Mac 工作队列、执行器和 DM 历史保留。API 契约见 [api.md](api.md)；官方 SDK 桥接和 setup 见 [README](../scripts/raft-bridge/README.md)。

群身份以配置的 server/channel UUID为准，群名只在前后确认稳定ID后用于Raft SDK。实际成员接口不接受UUID，直接传UUID返回404；实现已改为读取当前 `#name` 并前后核对同名的稳定群ID，再通过实际profile核对每位成员ID。

发送前核对新鲜群版本、当前成员、冻结正文和真实worker租约；发送后读取provider消息，核对发送人、实际群/线程ID才记sent。未知回执停重发；SDK潜在POST重试被专用fetch挡住。旧DM入口不能提交、读取或取消内部群目标；旧DM合法发送仍保留独立兼容分支。

群不可读、权限撤回、成员未核对或过期时停群写入并撤下页面旧正文与回复，数据库历史保留。回复仅从实际发出根消息的线程读取，支持真人和Agent稳定身份，不读取inbox，不执行反向命令。当前回收窗口仍为最近30条已发送消息、每个线程最多50条，不能宣称全量同步。
